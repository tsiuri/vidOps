About Chunk Analysis

The Chunk Analysis pass is the foundation of the analysis pipeline. It breaks transcripts into chunks and analyzes each chunk with the LLM to extract main topics, content, and structure. Configure chunk size and speaker handling below.

Chunk Size & Processing

Default: 1000. Larger chunks capture more context but process slower. Smaller chunks are faster but may lose context.


Default: 150. Overlap allows chunks to share words at boundaries, preserving continuity. Set to 0 for no overlap. Multiples of 50 (e.g., 100, 150) work best with the default chunking heuristics.

Speaker Handling

When enabled, chunks are further broken down by speaker turns from the VTT file. This allows analyzing what each speaker said separately within each chunk. Requires subtitle/VTT data to be available.

ℹ️ How Chunks Are Processed

Basic Flow:

  1. Transcript is split into chunks of ~1000 words
  2. Chunks overlap by ~150 words to maintain continuity
  3. Each chunk is analyzed by the LLM for main topics and content
  4. If per-speaker subchunks are enabled, each chunk is further broken by speaker turns
  5. Results are stored in the database and aggregated

Downstream Impact:

  • Chunk size affects analysis depth and processing time
  • Larger chunks = more context but slower analysis
  • Smaller chunks = faster but may miss context across chunk boundaries
  • Overlap helps preserve continuity between chunks
  • Per-speaker subchunks enable speaker-level sentiment and category analysis
